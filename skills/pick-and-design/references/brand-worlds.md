# Reference-inspired visual worlds

Use when the brief needs a distinctive image direction, reference-inspired alternatives, or revisions to an approved visual world. This is a web art-direction module. It does not require changing the brand, generating assets for every project, or importing an entire external skill collection.

## Inspect and extract

Inspect supplied images and relevant rendered pages before making visual claims. Identify each input's role: visual-language reference, current approved concept, product/content anchor or negative reference. A stylistic reference is not an edit target unless the user asks to preserve its pixels.

Record two lists:

- Transferable relationships: density, depth, palette relationships, lighting, material/texture, image treatment, typographic scale, composition rhythm and the role of people or objects.
- Source-specific identity: marks, slogans, recognizable arrangements, distinctive motifs, exact poses, branded objects and signature letterforms that will not be carried over.

Use qualitative proximity: distant inspiration, related visual language, or a closer interpretation of selected traits. Ask only when this choice materially affects the result. Do not present similarity percentages or a count of changed elements as proof of originality. Assess the overall result and distinctive combinations.

## Build direction cards

For one product, keep its name, purpose, audience, approved copy and key task constant across directions. Vary the visual storytelling, environment, medium, composition, motif and image treatment. Do not invent several brands when the user requested alternatives for one site.

Each card contains:

- Product message and intended feeling.
- Referenced visual relationships and explicitly excluded source identity.
- Typography/layout direction consistent with the project's visual constraints.
- Subject or activity, setting, light, surface and a product-relevant motif when useful.
- Placement in the web page, text-safe regions, crop behavior and narrow-screen treatment.
- Asset plan: existing owned material, licensed material, procedural implementation or image generation.

Prepare three distinct directions when the parent workflow calls for a choice. Do not produce three color swaps. When the user combines details, establish one primary direction and reconcile the others within it. Follow the parent's reference review and user-selection step before implementing the full site.

## Generate only what the brief needs

If image production is requested or necessary for the authorized deliverable, use the available image-generation tool and its skill guidance. Make each distinct concept a separately specified generation, not an ambiguous request for multiple identities in one image. Keep the skill usable without optional local MengTo skills or paid services.

Use a generation brief with: asset role, input roles, product meaning, subject/action, environment, medium, composition, lighting, palette relationships, crop/text-safe areas, required text if any, exclusions and output requirements. Preserve the user's actual brand name. Do not place a logo or wordmark into every image by default.

For website UI, render headings, controls and essential copy as live semantic text. Prefer text-free imagery with space for the UI overlay. If an asset genuinely needs lettering, verify exact spelling and unintended extra marks; correct it through supported tools rather than accepting unreadable text. A generated webpage image is not a working interface.

## Revise and preserve

On revision, use the original reference and the approved concept with their roles stated. Preserve the brand meaning and selected direction; change the requested variables deliberately. Keep previous asset versions and record why the new version supersedes them. Do not restart the visual world for a minor adjustment.

Inspect outputs for subject relevance, distinctive composition, crop/resolution, artifacts, lettering when applicable and compliance with typography/layout constraints. Correct observed failures with targeted iterations. Compare actual reference and output evidence before describing originality; missing reference access remains an uncertainty.

## Persist in the project

Add visual-world decisions, selected/rejected traits, asset provenance, generation briefs, versions and usage/crop rules to the existing project design-system module. Keep private reference captures local and out of public packages unless sharing is authorized. Record links and findings in public documentation instead of redistributing third-party reference artwork. This project's assets never become global skill defaults.
